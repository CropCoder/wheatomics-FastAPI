A · Quick start

How to use the agent

WheatOmics is built to be operated by AI agents. The fastest way to start is to give your assistant — Claude Code, Cursor, VS Code, ChatGPT or any agent that can read a URL or accept pasted text — the ready-to-copy prompt below. The agent reads the live OpenAPI schema and writes a reusable WheatOmics Data Query skill for your own workspace.

Copy-ready prompt

  1. Copy the prompt below.
  2. Paste it into your AI assistant, or attach it as a task in your agent's workspace.
  3. Keep the output — the assistant returns a reusable skill file (for example SKILL.md) plus an optional wheatomics.py helper; load it in later conversations to query the platform directly.
Please read the WheatOmics platform OpenAPI documentation:
https://wheatomics.sdau.edu.cn/api/docs
Machine-readable schema:
https://wheatomics.sdau.edu.cn/api/openapi.json

Based on that documentation, generate a "WheatOmics Data Query" skill for me.

Requirements:
1. Cover every module in the documentation — gene search, expression profiles, sequence retrieval, BLAST, synteny, variation data, literature, and any other module you find.
2. For each module, document its endpoints, parameters, response format, call examples and important notes.
3. Organize the result into a reusable skill file that can be loaded directly in later conversations.
4. Generate everything strictly from the actual endpoint definitions in the OpenAPI document — never invent endpoints that do not exist.
5. Write this hard rule into the skill: whenever an answer involves a specific gene ID, pathway ID (GO/KEGG) or cited reference (PMID/DOI), you MUST call the corresponding API endpoint to verify it in real time. Never rely on memory or guesswork, and never present anything as fact unless it came from an actual API response.
6. Add an "automatic result persistence" convention to the skill: whenever a query produces results the user may want to cite or reproduce later (gene details, expression profiles, BLAST hits, enrichment results, literature, etc.), write them to local files (JSON / Markdown report) by default instead of leaving them only in the conversation. Document the save-to-file usage `wheatomics.py ... -o <file>` and suggest an output directory (for example `./wheatomics_results/`).
Works in any assistant that accepts pasted text. Prefer a native MCP connection instead? See the MCP server section.

What the generated skill contains

  • Every platform module: gene search, expression profiles, sequences, BLAST, synteny, variation data, literature and more.
  • For each module: endpoints, parameters, response format, call examples and notes.
  • A verification rule for gene IDs, GO/KEGG pathway IDs and PMID/DOI references.
  • An output convention that saves query results to JSON / Markdown files.

Why the verification rule matters

WheatOmics identifiers are easy to misremember: one gene ID may exist in several reference genomes, GO/KEGG terms change between releases, and a cited paper may not support the claim it is attached to. The generated skill therefore requires a live API call before any concrete ID or reference is reported — every answer stays traceable to an actual API response instead of model memory.

Read access needs no API key; see access & support for write access and contacts.

B · Model Context Protocol

AI agents: built-in MCP server

WheatOmics runs an MCP (Model Context Protocol) server over SSE (Server-Sent Events), so an MCP-capable AI client can connect remotely, discover the tools below and call them as native tools. The server exposes sequence retrieval and CAPS/dCAPS primer design; the REST API described in the next section covers the remaining data modules.

Server and endpoints

Connect to the public host https://wheatomics.sdau.edu.cn:

ItemValue
Server namewheatomics
TransportSSE (Server-Sent Events)
SSE endpointGET /api/mcp/sse
Message endpointPOST /api/mcp/messages

Connect an MCP client

Add the remote SSE server to your MCP client's JSON configuration. The mcpServers form shown here is what Cursor and many other clients use; some clients spell the key servers and accept the transport implicitly, so check your client's schema:

{
  "mcpServers": {
    "wheatomics": {
      "type": "sse",
      "url": "https://wheatomics.sdau.edu.cn/api/mcp/sse"
    }
  }
}

Claude Code can register the same server from a shell:

claude mcp add --transport sse wheatomics https://wheatomics.sdau.edu.cn/api/mcp/sse

Check connectivity — the stream opens with an SSE endpoint event that carries the message URL:

curl -N https://wheatomics.sdau.edu.cn/api/mcp/sse

Your client must support remote SSE MCP servers; local stdio-only clients cannot connect to this endpoint directly.

Registered tools

Four tools are registered on the server. Arguments are passed as the tool input object; errors come back as text so the model can adjust and retry.

Tool Required arguments Optional arguments Returns
get_sequence_by_gene gene_id gene_db (default all_gene), protein_db (default all_protein) Gene and protein FASTA records for one gene ID.
get_sequence_by_interval region (legacy format, e.g. chr1A:10-100), database (a genome database name) — FASTA sequence for the requested genomic interval.
batch_sequence database, ids (space-separated gene IDs) — Direct-entry FASTA records for multiple gene IDs.
design_caps_primers seq1, seq2 (equal length, one base differs) mismatch_max (0–3, default 1), top_n (default 10) Ranked CAPS/dCAPS designs with enzyme, primer sequences, mismatches, cut position and Tm.

C · Representational State Transfer

REST API

Every data module is also reachable over plain HTTP under the base URL https://wheatomics.sdau.edu.cn/api. The interactive references are the quickest way to explore the endpoints: Swagger UI, the ReDoc reference, or the machine-readable OpenAPI 3.x schema.

Response envelope

Successful calls are wrapped consistently, with the payload under data:

{
  "success": true,
  "message": "ok",
  "timestamp": "2026-10-29T02:15:00+00:00",
  "data": { }
}

The timestamp is regenerated on every response. Validation errors (HTTP 422) and unexpected server errors (HTTP 500) return the same envelope with "success": false, an error summary and a detail field; endpoints can also answer with a plain HTTP error status and a detail message.

Quick start

Application metadata:

curl https://wheatomics.sdau.edu.cn/api/about

It returns the API name, version, docs, api_prefix, server_time and client_ip.

One page of the curated known-gene list:

curl "https://wheatomics.sdau.edu.cn/api/genes/known/all?limit=2"

GET /api/genes/known/all accepts optional limit (1–5000) and offset (≥ 0); without limit it returns the full list.

Long-running BLAST jobs

BLAST is asynchronous: POST /api/blast/search queues a job (form fields such as program, database and query), and GET /api/blast/status/{job_id} reports the status and download links. Send wait=false to get a job_id back immediately instead of waiting for the result.

Why this matters for agents

Give an LLM the OpenAPI JSON — or connect the MCP server — and it can discover the available data endpoints and call them on its own. Responses are already machine-friendly JSON under the unified envelope, so no scraping or ad-hoc parsing is needed.

D · Access & support

Access & support

Access

All read endpoints are public and need no API key. Write endpoints — such as the curated known-gene write API at /api/genes/known/write — require an API key issued by the maintainers; the key is sent in the Authorization: Bearer or X-API-Key header.

Keys are scoped, rate-limited and audited, and are only issued for curation work. Email shengweima@icloud.com to request one or to report a problem.

Support

Questions, bug reports and feature requests are welcome by email at shengweima@icloud.com.
