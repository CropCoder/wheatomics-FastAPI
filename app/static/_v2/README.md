# WheatOmics 2.0 shared shell (`app/static/_v2/`)

The V2.0 site chrome — theme tokens, header/nav, mega dropdown, footer, visit
statistics — lives in one place and is injected into every converted SPA.
The canonical source is the BLAST page (`app/static/blast2/index.html`), which
carries the exact chrome used by `/blast/blast.html` and the V2.0 pages.

Files:

| file | purpose |
|---|---|
| `shell.css` | V2.0 theme + header/footer styles + a Bootstrap 4 bridge (`.card`, `.btn`, `.form-control`, `.table`, `.nav-tabs`, `.badge`, `.alert`, `.modal`, `.dropdown-menu`, `.pagination`, `.progress`, plus `h1–h4`, `.container`, `.text-muted`) |
| `shell.js` | injects the SVG sprite, header and footer, wires the mobile menu, dropdowns, back-to-top and the footer visit statistics; marks the current nav entry |
| `template.html` | reference skeleton: copy the head/hero/main structure into a converted page |

Both files are generated by `scripts/extract_v2_shell.py` from the canonical
BLAST page. **Do not hand-edit them** — change the canonical page and re-run:

```bash
python3 scripts/extract_v2_shell.py
```

They are served by FastAPI at **`/api/v2shell/`** (mounted in `main.py`).
The `/api/` prefix is deliberate: Apache already proxies `/api` to the backend,
so no new `ProxyPass` rule is needed.

## Converting a SPA

A converted page keeps its own markup and JavaScript; only the page frame is
replaced.

1. **Head** — keep `charset`, `viewport` (add it if missing), a
   `Module | WheatOmics 2.0` title and `/favicon.ico`; keep the page's existing
   local assets (Bootstrap 4.5.3 CSS/JS, jQuery, Select2, Plotly …); then add
   the shell stylesheet **after** them so it wins the cascade:

   ```html
   <link rel="stylesheet" href="/api/v2shell/shell.css">
   ```

2. **Remove the old frame** — delete the legacy header/tabs (`#home_header`,
   `#header-tabs`, old top nav bar), the legacy footer (`#home_footer`, logo
   strip, `#visit-stats`) and the per-page `/api/track/visit` + `/api/track/stats`
   script block (the shell handles visits).

3. **Insert the shell frame**:

   ```html
   <body>
     <div id="v2-shell-header"></div>
     <main id="main-content">
       <section class="news-hero"> … page title + one-line lead + stats … </section>
       <section class="news-body"><div class="container"> … existing content … </div></section>
     </main>
     <div id="v2-shell-footer"></div>
     <script src="/api/v2shell/shell.js"></script>
     … page JS …
   </body>
   ```

   The shell's `main { padding-top: 88px }` clears the fixed header.

4. **Hero block** (matches the BLAST page):

   ```html
   <section class="news-hero">
     <div class="container news-hero-inner">
       <div>
         <p class="news-kicker">WheatOmics 2.0 · Analysis tool</p>
         <h1 class="news-title">Module<em>name</em></h1>
         <p class="news-lead">What the tool does and what the user gets back.</p>
         <div class="news-stats">
           <span class="news-stat"><strong>N</strong> items</span>
           <span class="news-stat">Short capability</span>
         </div>
       </div>
       <div class="news-hero-mark" aria-hidden="true"><svg class="icon"><use href="#i-search"/></svg></div>
     </div>
   </section>
   ```

   Available sprite icons: `i-search`, `i-dna`, `i-leaf`, `i-grid`, `i-sequence`,
   `i-network`, `i-flask`, `i-chromosome`, `i-wave`, `i-marker`, `i-gene`,
   `i-nodes`, `i-primer`, `i-scan`, `i-helix`, `i-book`, `i-globe`, `i-chart`,
   `i-cells`, `i-shield`, `i-scissors`, `i-mail`, `i-pin`.

5. **Restyle page-specific CSS** with the V2.0 tokens instead of hard-coded
   colours (the tokens are already defined by `shell.css`):

   ```
   --forest #07583d   --forest-deep #033f2d   --leaf #118653   --sprout #77b941
   --wheat #e6b94a    --mist #f3f8f4          --ink #163128     --muted #66766e
   --line #dfe9e2     --shadow 0 12px 36px rgba(8,69,47,.09)
   --display "Avenir Next", "Segoe UI", Arial, sans-serif
   --body Arial, Helvetica, sans-serif   --utility "IBM Plex Mono", …monospace
   --page min(1400px, calc(100% - 48px))
   ```

   Prefer the shared components: `.card`/`.card-body`, `.btn.btn-primary`,
   `.form-control`, `.table`, `.nav-tabs`, `.badge`, `.alert`, `.v2-tool-head`,
   `.v2-section-title`, `.v2-chip`, `.v2-mono`. A `--page`-wide wrapper is
   `.container`.

6. **Keep functional IDs and JS untouched** (`#gene-input`, result containers,
   chart divs, onclick handlers …). Only the surrounding frame changes.

## Verification (required before commit)

```bash
# 1) syntax / assets
node --check app/static/_v2/shell.js
python3 - <<'PY'
import re, pathlib
t = pathlib.Path("app/static/<module>/index.html").read_text()
assert "api/v2shell/shell.css" in t and "api/v2shell/shell.js" in t
assert "home_header" not in t and "header-tabs" not in t and "visit-stats" not in t
print("frame OK")
PY

# 2) local render check — serve a scratch copy so /api/v2shell resolves
rm -rf /tmp/v2test && mkdir -p /tmp/v2test/<module> /tmp/v2test/api/v2shell
cp app/static/<module>/index.html /tmp/v2test/<module>/
cp app/static/_v2/shell.css app/static/_v2/shell.js /tmp/v2test/api/v2shell/
(cd /tmp/v2test && python3 -m http.server 8011 >/dev/null 2>&1 &)
bash scripts/spa_visual_check.sh http://127.0.0.1:8011/<module>/ --widths 390,768,1440

# 3) after deploy — live check (Lead runs this per batch)
bash scripts/spa_visual_check.sh https://wheatomics.sdau.edu.cn/<module>/ --widths 390,768,1440
```

Expect: `Result: PASS`, header + footer injected, nav entry highlighted,
no horizontal overflow at 390/768/1440, no JS errors, no broken `<img>`.

### Serving note: `/neighborhood/`

Apache's vhost has no `ProxyPass /neighborhood`, so that module is served
straight from the docroot through a symlink to the repo directory (works because
`/var/www/html` allows `FollowSymLinks`):

```bash
ln -s /var/www/FastAPI_backend_Port8000/app/static/neighborhood /var/www/html/neighborhood
```

Do NOT copy the page into `/var/www/html/neighborhood/`: the symlink keeps the
docroot copy in sync with `git pull`. If a real `ProxyPass` is added later,
delete the symlink.
